# Intentional behavior changes

The canonical installed package changes unsafe or ineffective legacy behavior. Original executable sources remain frozen in `tests/fixtures/legacy/` as characterization inputs, not runtime fallbacks. Both root launchers execute the installed module with the same interpreter and `-I`. `VERIFICATION.md` records exercised source, installed, artifact and operational checks separately from historical failures and unavailable scope; authored coverage is not a passing gate.

| Boundary | Canonical behavior and migration |
|---|---|
| File authority | Mutating commands preview by default. Grant local publication with invocation `--apply`; remote effects and torrent removal require their separate explicit flags. Settings do not grant mutation authority. Preview may use cleaned scratch and explicit external plan/profile files, not persistent library or journal writes. |
| Numeric parsing | Decimal values, missing values, sets, ranges and parts remain distinct. Four labeled explicit-set corpus corrections are recorded in the modern characterization report; no blanket legacy-parity claim follows from those corrections. |
| Paths and publication | Plans bind observed bytes, root permissions and collision state. Locks are written only at explicitly writable mutation boundaries; read-only import sources remain untouched, including when a writable state directory is nested beneath them. State initialization takes the ownership lock before SQLite may repair a hot journal. Source cleanup occurs after verified group commit, with original bytes retained. Conflicts, unavailable evidence and ambiguous matching require review instead of speculative overwrite or deletion. |
| Artwork | Timestamp equality is not ownership. Only proven generated/relevant artwork may be replaced or retired; custom artwork is preserved or blocks the group for review. Actual encoded format determines suffix and MIME. Missing default series artwork is still `cover` only: the legacy cover/poster recognition list never meant creating both. Valid uppercase raster suffixes are accepted rather than excluded solely by spelling. |
| Archive inputs | Header identity, bounded expansion and complete member/source evidence replace trusting the filename alone. Each RAR/7z/image/HTTP job has a dedicated subreaper supervisor and resource-limited decoder; the application process does not adopt unrelated orphan children. A decoder exiting without a result fails immediately after owned cleanup rather than waiting for a needless pipe deadline. Missing licensed ISBN/EPUB implementation sources yield an explicit prerequisite failure, never a successful empty conversion. |
| HTTP delivery | TLS verification, scoped redirects/cookies, decoded-byte limits and total process deadlines are enforced. Cancellation kills and reaps owned wire work. A timeout or local parsing failure after a mutation may have been sent remains pending-unknown; no exactly-once or blind-replay claim is made. |
| Komga endpoint | A complete URL may contain its own port or use the scheme default with `komga_port = ""`, as the original allowed. Prefixes and explicitly configured overrides remain subject to URL validation. |
| Dictionary entries | Imported names are literal data, escaped before regex compilation. Committed maintenance refreshes the same pipeline's parsing/rename policy and policy identity. Invalid lists do not silently authorize work. |
| Obsolete controls | Remove `cache_each_root_for_each_path_in_paths_at_beginning_toggle` and `short_word_filter_percentage` from canonical TOML, KCE environment and CLI overrides: they now reject instead of accepting no-op controls. Inventories are fresh rather than trusting a persisted path cache. The original shortened-word slices never affected its return decision. Safe legacy settings migration validates and omits the historical cache boolean; all other supported original literals still migrate. |
| Recovery cancellation | Cancelling recovery preserves durable unfinished work without poisoning it as needs-review solely because of cancellation. Later explicitly authorized recovery revalidates and resumes; genuinely stale/conflicting/unknown evidence still requires review. |
| Observability | Counts reflect committed, skipped, failed and deferred work rather than attempted writes. Profiling executes the selected real service without evaluating source. Ancillary logging failures do not rewrite already committed counts. |
| Post-commit ancillary failures | Lazy Discord, Komga and BookWalker setup failures retain already committed counts and operation reports. A bad integration configuration cannot rewrite completed local history into a zero-commit response. |
| HTTP timeout configuration | Connect, read and BookWalker timeouts must not exceed the existing 60-second transport budget. Invalid values reject before local mutation instead of failing only when a client is constructed afterward. |
| Torrent retries | Known-undispatched failures remain pending and may be claimed only by a fresh authorized invocation that revalidates current policy, torrent identity, progress and library evidence. Dispatched or uncertain mutations remain non-replayable. |
| Delivery scope | An out-of-scope pending row remains review-required without starving unrelated authorized operations in the same state store. |
| Recovery accounting | A completed operation or cleanup-only retry reports zero newly committed local groups. Recovery that first commits an unfinished group reports one. Existing files, journal identity and committed outbox events remain authoritative; pending delivery still settles independently when authorized. |
| Definite-unsent HTTP failures | Supervisor quota rejection, pre-spawn cancellation and launch failure return typed `HttpError` with `pending_unknown=false`. `WorkerError.started=false` means a failure known to precede successful `Popen`. Successful process launch remains the conservative uncertainty boundary for mutations. Post-wire uncertainty is not automatically replayed. |
| Watch review retention | Committed groups with failed or unknown hook settlement retain bounded durable delivery-review obligations across restart. Settling an outbox row cannot erase an independent interrupted-generation review obligation. A known changed fingerprint can create a new observation without replaying the old generation. |
| qBittorrent host input | Legacy `qbittorrent_ip` accepts a bare host such as `127.0.0.1` and defaults to HTTP. Explicit HTTP(S) URLs retain their existing validation. The real read-only CLI proof authenticates, reads the server version and reads torrent information without creating state or granting mutation authority. |
| Organizer ownership | An incoming destination joins the existing series owner's group. The projected catalog describes logical post-plan names but does not own publications. Only the current group's operation reasons and source artifacts may supply publication destinations and changes. An earlier group's projected publication cannot become a second plan for the same fingerprint. |
| Watch admission fairness | Apply-root discovery uses the same bounded per-root cursor approach as preview. The coordinator checks capacity before discovery or advancing the cursor so full capacity cannot discard an unadmitted observation or starve later inputs. |
| Watch history limits | Active negative-cache, pending and review work is bounded. Completed durable journal history is uncapped. Finite 512-tick receipts prove their recorded observations, not an asymptotic memory bound. |
| Lock-release diagnostics | A journal-owner or lock-metadata release failure adds a failure to the existing result instead of erasing completed counts, plans or deferred work. Completed apply paths return after release diagnostics. Verified local commit events remain independently deliverable; nonzero exit is retained. |
| Metadata observation scope | Selected full-run work observes its own series metadata. Other series are decoded only when active matching or cross-library artwork copy needs that evidence. Unrelated malformed metadata cannot fail an otherwise valid selected artwork run. Required matching still treats unavailable metadata as unavailable, not an empty catalog. |
| Organizer preparation scope | Matching preflight runs only for an enabled matching stage and selected download work. Its required candidate freshness remains checked. Sidecar association uses one folder/stem index, retaining insertion order, suffix rules and shared-stem conflict handling instead of rescanning every file for every book. |
| Gap-report authority | `missing-releases` reports the complete available configured catalog. A public selected-book request narrows returned release records, not the sibling/folder evidence used for gap detection. Any unavailable library still rejects an apparently complete report. |

These dispositions do not turn authored coverage into exercised acceptance. The matrices retain ownership, callers, proof and named gaps. Current source, installed consumer and actual-image proofs pass; the previous full book benchmark is historical after the dedicated-supervisor change, with current measurement recorded separately in `VERIFICATION.md`. Formatting119 fails, completed durable history is uncapped, and unavailable platform/licensed/live evidence remains explicit. Linux/local filesystem and localhost protocol evidence is not Windows/NTFS/macOS/ARM64/NAS/live BookWalker parity.
