## Module names and call boundary

Names below are relative to `src/komga_cover_extractor/`. `filenames`, `numbers`, `normalization`, and `metadata` are in `parsing/`. `classification`, `ranking`, `series`, and `cover_similarity` are in `matching/`. `selection` and `series_policy` are in `covers/`. Workflow names and `Pipeline` are in `application/`. `ArchiveReader`, the native readers, `TransactionExecutor`, `StateStore`, `RunObservability`, and image output policies are in `infrastructure/`. `HttpClient`, `DiscordDelivery`, `bookwalker`, `komga`, and `qbittorrent` are in `integrations/`. `legacy_cli` is in `compat/`. This is the current module layout, not the handoff's proposed filenames.

`kce` and `python -I -m komga_cover_extractor` enter `cli.main`. Library commands use `open_pipeline(config, request=request)` and `Pipeline.run`. `watch` owns one `WatchCoordinator` around that pipeline. `qbit` calls `run_torrents` with `Pipeline.library_snapshot` as its fresh catalog provider. `serve` supervises installed run/watch and optional qbit children. Both root launchers now use guarded stdlib-only same-interpreter `-I` installed-module exec. Root `tests.py` is a guarded modern pytest runner. No executable settings import, wildcard add-on import, or monolith runtime fallback remains. Frozen originals retain their characterization role.
