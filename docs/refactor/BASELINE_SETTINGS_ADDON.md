## User-visible add-on behavior and compatibility requirements

1. **Invocation and startup** — :58-78 exposes only argparse `-p/--paths` (required, append, nargs='*'), `-df/--download_folders` (optional, append, nargs='*'), plus automatic help. Required `-p` can appear without values and produce no usable paths; no semantic path validation blocks the polling loop. No once/dry-run/apply/init subcommand or environment parser exists. Only the :579 main guard starts polling/profiling; argument parsing, path printing, logging, cache setup and regex compilation occur even on import. Modern helper needs a cheap import plus independent CLI entry point; retain repeatable path arguments via compatibility adapter and add explicit safe invocation semantics.
2. **Legacy path grammar** — :81-146 split literal backslash-one (`\\1`) in first token into separate root arguments, then literal backslash-zero (`\\0`) into root/restriction tokens. Plain repeated groups also work. Shared M:1146-1326 accepts file-format, allowed-extension, configured library-type and translation-source restriction tokens; only provided metadata produces typed Path under normal non-watch conditions. It appends roots to shared lists. Source-language list is initialized but no token branch populates it. Do not call these NUL/SOH bytes; they are printable legacy delimiters. `--download_folders` help :72 advertises optional commented processing/renaming/moving calls at file bottom, but complete source contains no such calls: option supplies matching/cache context only. Report dormant advertised processing, not a functioning post-download pipeline.
3. **Cache initialization** — :149-177 loads cache only with check_for_existing_series_toggle, no existing cache and local toggle; filters filesystem existence; otherwise may recursively scan libraries, even before helper enable/endpoint checks. M:1103-1139 reads real paths and uses lexical startswith; M:10778-10810 walks directories and calls M:2060-2071 cache_path; M:4233-4284 write_to_file creates logs directory before checking can_write_log. A stale/empty loaded cache can rebind addon cache to a different list while main cache_path mutates main's list. Keep library observation/cache interfaces independent, with component-prefix containment and explicit state synchronization. No import-time scan/write.
4. **Login / disabled modes** — :503-520 returns normally (no nonzero status specified) when helper disabled, endpoint/port absent or category absent, after prior import work. :466-484 constructs Client from settings, blank credentials become None, explicit auth_log_in occurs only when both present. :488-500 additionally demands is_logged_in; :529-547 retries indefinitely every 60 seconds. There is no explicit logout, client close, request timeout configuration, graceful shutdown handler or single-run mode. SDK defaults must not be misreported as application-configured bounds. Modern credentials/availability validation must occur before effects, retain explicitly supported unauthenticated deployments, and have bounded failure/shutdown contracts.
5. **Torrent discovery / ordering** — :197-198 calls qb.torrents.info(), then accesses `.files.data` to discard torrents lacking metadata. It does this BEFORE category/state filter :181-188, so irrelevant torrents' files may be requested. :549-562 selects exact target category and pausedDL/stoppedDL, excludes the inert processing list, sorts by file count ascending (stable ties), then processes sequentially. No tag read/mutation, category assignment/creation, tracker changes, add-torrent, or torrent-content movement exists. Repeated `.files` property reads cause repeated SDK API calls (upstream v2025.7.0 source 2302-2304). Preserve relevant ordering but observe each metadata snapshot once and explicitly handle not-ready/disappeared torrents.
6. **Unacceptable keywords** — :361-387 first checks whole torrent name only with all necessary policy flags; on match returns every file without individual priority writes or final summary. Otherwise case-insensitive basename regex matches are individually unchecked immediately. No downloaded file is deleted by this stage; method/comment says delete loosely. Preserve basename/title distinction and clarify selection versus torrent removal.
7. **Filename parsing** — :267-292 uses each torrent-relative path's immediate parent basename, or torrent.name when rootless, as synthetic `/{dir_name}` root; only file basename is parsed. File factory gets convertible+accepted extensions and test_mode=True but NOT clean=True; M:2276-2283 therefore does not run extension/chapter filtering. Unsupported filenames are not guaranteed excluded. Volume factory skips release year/group/extras/publisher/premium/subtitle and uses test_mode=True, but still parses multi-volume and file parts. M:3533-3549 sets one-shot volume=1 and folds parts into decimal index. Do not infer 'test_mode' is a sandbox for the surrounding matching workflow. Shared public filename-only parser must preserve raw torrent identity while providing equivalent parse data.
8. **Series matching** — :297-349 temporarily converts convertible file's name/extension to `.cbz` for library comparison (no archive conversion). Cache key is series_name + file_type + extension; caches and negative matches are local to one torrent. Calls shared matcher with one synthetic volume, paths, typed paths, cached_paths and download_folders or overwritten ROOT_DIR. A no-match skips exclusions; later :435-440 starts torrent. Thus missing/unavailable library state conflated with no match is fail-open. Modern matcher must return explicit unmatched versus unavailable/ambiguous/error, with unknown policy failing closed per SPEC; record as intentional safety change.
9. **Upgrade/new decision** — :214-237 scans existing_files in order, first `is_same_index_number` match wins. Case-insensitive identical names are never upgrades; otherwise main is_upgradeable uses strict greater sum of case-insensitive ranked matches. No same index => new item kept. Main M:2465-2474 compares exact nonempty equality by default; addon does not opt into scalar/range inclusion. Empty ranking list => all matched scores tie, so reject same-index replacements; new indices remain kept. Preserve tie ordering, first-match semantics, case rule, file_type applicability, negative scores and range/part quirks until explicitly corrected.
10. **File identity hazard** — :395 builds `{basename: file}`; later :342 uses original parsed basename to choose actual file index. Two folders containing same basename collapse to the last item; repeated decisions can uncheck the wrong index or append the same object repeatedly. :435 decides all-excluded via LIST LENGTH equality, not unique excluded indices, so duplicates can corrupt start/remove decision. Migration must retain torrent hash + stable file index + full torrent-relative path; classify this correction and preserve raw extension independently from comparison extension.
11. **Priority effect** — :415-417 calls qb.torrents.file_priority(hash, file_ids=[index], priority=0), one call per exclusion, during decision traversal. Does not reset retained files to positive priority or honor current disabled count when computing exclusions; user-preexisting zero priorities remain zero. Refactor decisions before effects and revalidate current torrent/files snapshot; characterize existing priorities, partial success and failure.
12. **Start/remove** — :431-447 reads current files then check_files; if excluded count differs from file count starts torrent via torrent.start(); otherwise torrent.delete(). No additional confirmation, invocation apply authorization, category/state refresh or existence check. Logs announce action before action succeeds. This is remote mutation despite helper's 'uncheck' name. Default new behavior must not send start/removal/priority writes during preview, and torrent removal must require independent explicit authorization. Content deletion is not a legacy enabled option; do not introduce it through a default.
13. **Exceptions / retry** — :563-570 catches per-torrent exceptions and continues; already applied priority changes stay applied, then normal loop sleeps. :572-576 catches outer failures without sleeping, potentially hot-looping on info/login-status/sort failures; a client that remains is_logged_in may not be reconnected. :585-589 logs top-level Exception and returns, but argparse SystemExit and KeyboardInterrupt are outside that catch. No durable operation ownership or reconciliation. Modern tests must cover unknown delivery and ensure failed effects are not logged/count-returned as committed success.
14. **Dormant helpers and state** — `torrent_exists` :192-193 has no caller and is not a pre-action guard; `process_torrents` :451-462 has no caller because main calls process_torrent directly. processing_torrents list never gets additions. Comments about file-count limiting at :362 have no actual limit. Do not migrate these names as working capabilities without explicitly delivering behavior.
15. **Logging** — send_message_alt :42-55 prints and writes by default regardless of settings.log_to_file. Main write_to_file uses shared repo logs path, strips tabs/newlines and timestamps content. Error exception strings and filenames are directly printed/written; there is no secret redactor. Path output with typed library restrictions uses this writer even at import. Separate public stdout diagnostics, redacted errors and optional persistent logs.
16. **Deployment consumer** — Dockerfile:35-36 installs addon requirements; :68 unconditionally launches this helper in background with encoded PATHS/DOWNLOAD_FOLDERS and redirects stdout+stderr to /dev/null while main runs in foreground. Independent helper invocation path and shared config/resources matter; source enablement does not prevent startup import effects. Deployment owner must preserve lifecycle intentionally rather than remove helper as unrelated.
